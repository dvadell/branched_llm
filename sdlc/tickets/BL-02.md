----
title: Supervise the ChatOrchestrator TaskSupervisor under an OTP application
----

`BranchedLLM.ChatOrchestrator` runs every LLM request inside a `Task` started
by a `Task.Supervisor` that is currently **not part of any supervision tree**.
`ensure_started/0` calls `Task.Supervisor.start_link(name: @task_supervisor)`
on first use, which **links the supervisor to the calling process**. That is
fragile in a web application:

- The caller is typically a short-lived request process (Phoenix controller,
  LiveView `handle_event`, etc.). If that process crashes with a non-normal
  exit, the linked supervisor (and every in-flight LLM task) is killed.
- The supervisor lifetime is coupled to whichever process happened to be the
  first caller; a process that exits normally keeps the supervisor alive but
  the relationship is incidental.
- `ensure_started` is racy: two processes can observe `nil` and both try to
  start, one of them failing with an `{:error, {:already_started, pid}}`
  that is currently ignored.

## Scope

1. Add a proper OTP application to `branched_llm`:
   - New `lib/branched_llm/application.ex` — `use Application`, `start/2`
     starts a supervisor tree that includes a `Task.Supervisor` named
     `BranchedLLM.ChatOrchestrator.TaskSupervisor`.
   - Update `application/0` in `mix.exs` to `mod: {BranchedLLM.Application, []}`
     (keep `extra_applications: [:logger]`, add whatever the supervisor needs).
2. Replace the ad-hoc `ensure_started/1`:
   - `ChatOrchestrator.run/1` should no longer lazily start the supervisor; it
     assumes the app is started (standard for a dependency).
   - Keep `start_link/1` available for tests / overridable supervision, but the
     running app owns the supervisor.
   - Remove the now-dead `ensure_started` path (or keep a defensive
     `start_child` only). Watch the retry/`do_process` paths for assumptions.
3. Make sure `Chat.send_message/3` / `ChatOrchestrator.run/1` behave identically
   when the app is started by the host application (e.g. the umbrella), and that
   tests still work when the app is not started (check `mix test` with and
   without the new `mod:` — the e2e tests use the orchestrator directly).
4. Ensure clean shutdown: on app stop, in-flight tasks are terminated as the
   supervisor shuts down (default `:one_for_one` is fine).

## Acceptance criteria

- [ ] `branched_llm` has an Application module; the `TaskSupervisor` is started
      under it and is a supervised child.
- [ ] `ChatOrchestrator.run/1` no longer lazily `start_link`s the supervisor.
- [ ] A request process that crashes (raise inside a test caller) no longer
      takes down the supervisor: verify with a test that starts a task, crashes
      the caller, and confirms subsequent `run/1` calls still work.
- [ ] `MIX_ENV=test mix test` stays green (after BL-01).
- [ ] No behavioral change for the `BranchedLLM`/`Chat` public API.

## Verification

- `MIX_ENV=test mix test` (branched_llm).
- A small test in `test/unit/` proving supervisor survival across caller
  crashes (e.g. spawn a caller that calls `run/1` then exits `:normal`, and one
  that raises; both cases the named supervisor is still alive afterwards).
- `mix precommit` before considering the ticket done.
